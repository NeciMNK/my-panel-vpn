# my-panel-vpn

Личная панель управления VPN-серверами на базе [3x-ui v3](https://github.com/MHSanaei/3x-ui)
с подходом [Remnawave](https://github.com/remnawave/panel): один мастер управляет всеми
серверами (нодами), а пользователи получают одну подписку на всё сразу.

От 3x-ui взяты ядро, интерфейс и все протоколы Xray. От Remnawave взяты идеи: добавление
ноды одной командой, конфиг нод с мастера, страница подписки с инструкцией по установке
приложений. Код Remnawave (TypeScript, AGPL-3.0) в проект не входит.

> [!IMPORTANT]
> Проект для личного использования, не продукт и не сервис. Используйте только в рамках закона.

## Возможности

### Мастер и ноды

- **Мастер + ноды.** Мастер хранит пользователей, inbound'ы и настройки Xray и сам
  раскатывает их на ноды по HTTPS с mTLS. Трафик, онлайн и состояние нод собираются на мастере.
- **Нода одной командой.** На странице «Ноды» мастер выдаёт одноразовую команду (токен
  живёт час). Скрипт на новом сервере ставит сборку мастера, выпускает сертификат, создаёт
  токен синхронизации и сам регистрируется. Ручной ввод адреса, порта и ключей не нужен.
- **Xray нод с мастера.** На странице Xray есть выбор сервера: outbound'ы, маршрутизация,
  балансировщики, DNS и WARP любой ноды редактируются прямо с мастера.
- **PostgreSQL** как основная база (SQLite остаётся вариантом для простого случая).

### Каскады и балансировка

- **Каскад в 2 клика.** Выбираете входной сервер и один или несколько выходных. Панель сама
  поднимает на выходах скрытый VLESS+REALITY со своими ключами, а на входе прописывает
  outbound'ы и правило маршрутизации. В подписке пользователя остаётся только вход.
- **Балансировщик по стране.** Выходом каскада можно указать «все серверы страны» (например,
  DE). Новая нода этой страны попадает в балансировщик сама, трафик уходит через самый
  быстрый сервер (`leastPing`; доступны также `leastLoad`, `random`, `roundRobin`).
- **Липкие сессии.** Пользователь закрепляется за одним выходом, чтобы внешний IP не прыгал.
  Закрепление держится 15 минут после обрыва и сбрасывается, если пользователь сам выбрал
  другой сервер или выход упал.
- **Минимальная и максимальная скорость на пользователя.** Максимум жёстко режется через
  `tc` на всех серверах, где пользователь был в последние 30 минут. Минимум работает как
  порог качества: новый пользователь каскада попадает на выход, где эта скорость ещё есть,
  а если таких нет, админу уходит уведомление в Telegram.

### Сети

- **WARP одним переключателем** для каждого сервера на странице «Ноды»: выключен,
  весь трафик или только выбранные сайты. Регистрация WARP происходит сама.
- **Домашняя сеть.** Доступ к домашней локалке через один сервер-шлюз, который держит
  туннель WireGuard, OpenVPN или L2TP/IPsec. Подсети и отдельные IP задаются вручную, а
  правила доступа выдают пользователю или группе всю сеть, часть подсетей или отдельные
  адреса. Остальным пользователям домашние адреса закрыты. Остальные серверы ходят к шлюзу
  через скрытую связку VLESS+REALITY.

### Пользователи

- **Страница подписки с инструкцией.** При открытии ссылки в браузере определяется
  устройство (iOS, Android, Windows, macOS, Linux), пользователь выбирает приложение и
  добавляет подписку в одно нажатие. VPN-клиенты по той же ссылке получают обычную подписку.
- **Telegram-бот с оплатой.** Клиент видит в боте дату и сумму оплаты и реквизиты, жмёт
  «Я оплатил», админ подтверждает одним нажатием. Есть оплата на несколько месяцев со
  скидкой, отсрочка на 15 дней для доверенных клиентов и бесплатный тариф по заявке.
- **Переезд с Remnawave и 3x-ui без перевыпуска конфигов.** «Бэкап → Переезд с другой
  панели» импортирует пользователей, inbound'ы и хосты с сохранением UUID, паролей, ключей
  REALITY, subId, лимитов и трафика. Можно забрать и старый путь подписки, чтобы ссылки у
  пользователей продолжили работать. Пошаговый план переезда:
  [`migrate-from-other-panels.mdx`](docs/content/docs/ru/operations/migrate-from-other-panels.mdx).

### SSL

- **Сертификаты Let's Encrypt через Cloudflare DNS.** Панель сама выпускает сертификаты
  (включая wildcard, порт 80 не нужен), продлевает их за 30 дней до конца срока и
  раскладывает на все ноды. Настройки → «SSL-сертификаты», в форме TLS inbound'а есть выбор
  выпущенного сертификата.

### Всё, что уже есть в 3x-ui v3

- Все протоколы Xray: VLESS (REALITY, XTLS Vision), VMess, Trojan, Shadowsocks 2022,
  WireGuard, Hysteria2, TUIC v5, AmneziaWG, MTProto, HTTP/SOCKS, Tunnel, TUN.
- Транспорты TCP, mKCP, WebSocket, gRPC, HTTPUpgrade, XHTTP; fallback'и на одном порту.
- Лимиты трафика, сроки, лимит IP и устройств (HWID), группы клиентов, хосты для подписок.
- Подписки в форматах raw, JSON и Clash; REST API с токенами; 14 языков интерфейса.

## Установка

У форка пока нет своих релизов, поэтому штатный `install.sh` и команда `x-ui update`
ставят оригинальный 3x-ui. Мастер ставится в два шага.

**1. Сборка** (нужны Go 1.27+, Node.js 26+ с npm 11+ и компилятор C для SQLite):

```bash
git clone https://github.com/NeciMNK/my-panel-vpn.git
cd my-panel-vpn
cd frontend && npm ci && npm run build && cd ..
go build -o x-ui .
```

**2. Установка на сервер мастера.** Штатный установщик 3x-ui даёт systemd-юнит, меню
`x-ui`, Xray и PostgreSQL (выберите его при установке), затем бинарник заменяется сборкой форка:

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
systemctl stop x-ui
cp ./x-ui /usr/local/x-ui/x-ui
systemctl start x-ui
```

После этого не запускайте `x-ui update`: он вернёт оригинальный 3x-ui. Обновление форка —
пересборка и повторная замена бинарника.

**3. Ноды.** На мастере: «Ноды» → «Добавить ноду» → скопировать команду и выполнить её на
новом сервере. Она выглядит так:

```bash
curl -fsSL https://мастер/путь/node-join/install.sh | bash -s -- \
  --master https://мастер/путь --join <токен> --country DE
```

Нода скачивает сборку прямо с мастера, так что отдельно собирать её не нужно.

## База данных

Мастер рассчитан на PostgreSQL. Если установщик уже создал базу, он сам прописывает её в
`/etc/default/x-ui`:

```
XUI_DB_TYPE=postgres
XUI_DB_DSN=postgres://xui:пароль@127.0.0.1:5432/xui?sslmode=disable
```

Перенос существующей установки с SQLite:

```bash
x-ui migrate-db --dsn "postgres://xui:пароль@127.0.0.1:5432/xui?sslmode=disable"
# затем прописать XUI_DB_TYPE и XUI_DB_DSN в /etc/default/x-ui
systemctl restart x-ui
```

Файл SQLite при переносе не трогается, удалите его сами после проверки.

## Обновления из 3x-ui

Ветка начинается с полной истории 3x-ui, поэтому исправления оттуда подтягиваются обычным
слиянием:

```bash
git remote add upstream https://github.com/MHSanaei/3x-ui.git
git fetch upstream main
git merge upstream/main
```

Всё, что форк дописывает в шаблоны Xray, помечено префиксом `mp-<функция>-<id>-`, поэтому
каждая функция переписывает только свои outbound'ы, правила и балансировщики и не трогает
ручные настройки.
