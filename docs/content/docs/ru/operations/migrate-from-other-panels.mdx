Панель умеет забрать всё у Remnawave или другой 3x-ui и сохранить то, что уже
лежит у пользователей в приложениях. После переноса старые конфиги и старые
ссылки подписок продолжают работать, обновлять ничего не нужно.

## Что сохраняется

| Что | Remnawave | 3x-ui |
| --- | --- | --- |
| UUID VLESS, пароли Trojan/Shadowsocks | `vlessUuid`, `trojanPassword`, `ssPassword` | `id`, `password` клиентов |
| ID подписки (последняя часть ссылки) | `shortUuid` | `subId` |
| Путь и адрес подписки | из `subscriptionUrl`, например `https://sub.example.com/<shortUuid>` | `subPath`, `subJsonPath`, `subClashPath`, `subURI` |
| Порты, Reality-ключи, `shortIds`, SNI | из config profile | из подключения |
| Адреса, которые видит клиент | хосты Remnawave → хосты панели | `externalProxy` |
| Лимит и израсходованный трафик, срок, сброс трафика | да | да |
| Telegram ID, описание, лимит устройств (HWID) | да | да |
| Отключённые пользователи | остаются отключёнными | остаются отключёнными |
| Названия конфигов в приложении | ремарки хостов (шаблон `{{HOST}}`) | шаблон названий этой панели |

Не переносятся: маршрутизация, outbounds и DNS из config profile Remnawave
(настройте их в шаблоне Xray панели и нод), фильтры хостов по internal squads,
external squads, xhttp extra params хостов, подключения Hysteria. Списки
устройств HWID не переносятся: лимит сохраняется, а устройства регистрируются
заново при первом обновлении подписки. Если у пользователя Remnawave есть и
Trojan, и Shadowsocks с разными паролями, Shadowsocks получит пароль Trojan, и
этот один конфиг обновится только после обновления подписки. Окно переноса
показывает все такие случаи до импорта.

Исходная панель при переносе не меняется. Откат — просто снова запустить её.

## Окно переноса

**Обзор → Бэкап → Перенос с другой панели.**

1. Выберите источник.
   - **Remnawave**: адрес панели (например `https://panel.example.com` или
     `http://127.0.0.1:3000`, если панель на том же сервере) и API-токен
     (Remnawave → Settings → API Tokens). Если панель Remnawave отсюда не видна,
     загрузите файл-снимок (см. ниже).
   - **3x-ui**: файл `x-ui.db` старой панели (`/etc/x-ui/x-ui.db`).
2. Нажмите **Проверить**. Панель покажет серверы старой панели и куда их
   положить: на эту панель, на одну из нод или никуда. Ноды подбираются по адресу
   сервера автоматически. Ниже — подключения с конфликтами портов, число
   клиентов и пример старой ссылки подписки.
3. Оставьте включённым **Взять пути и адрес подписок старой панели**, чтобы
   старые ссылки открывались здесь же. Панель перезапустится.
4. Нажмите **Перенести**. Клиенты с уже занятым email пропускаются, повторный
   запуск ничего не дублирует, а всё, что не перенеслось, показано списком.

## Переключение с Remnawave

<Steps>
<Step>
### Поставьте ноды этой панели на серверы Remnawave

На каждом сервере, где работает `remnanode`, добавьте ноду этой панели
(**Ноды → Добавить**, одна команда). Remnanode пока не трогайте: у новой ноды
ещё нет подключений, поэтому порты не пересекаются.
</Step>
<Step>
### Проверьте перенос

Откройте окно переноса, введите адрес и токен Remnawave, нажмите **Проверить**.
Каждая нода Remnawave должна быть сопоставлена с нодой этой панели по адресу;
если нет, выберите вручную.
</Step>
<Step>
### Остановите remnanode и перенесите

На каждом сервере остановите старую ноду, чтобы освободить порты:

```bash
cd /opt/remnanode && docker compose down
```

Сразу нажмите **Перенести**. Подключения уйдут на ноды, Xray займёт те же
порты с теми же ключами. Перерыв — секунды между остановкой и импортом.
</Step>
<Step>
### Переключите домен подписок

Направьте домен подписок Remnawave (например `sub.example.com`) на сервер
подписок этой панели: смените DNS-запись или `proxy_pass` в nginx/Caddy на порт
подписок панели (по умолчанию `2096`), либо запустите сервер подписок прямо на
`443` с сертификатом этого домена. Путь уже настроен переносом (`/` для
Remnawave). Затем остановите контейнеры Remnawave и `subscription-page`.
</Step>
</Steps>

### Файл-снимок Remnawave

Если панель Remnawave недоступна с этого сервера, соберите снимок там, где она
доступна, и загрузите его в окно переноса:

```bash title="remnawave-snapshot.sh"
URL=https://panel.example.com
TOKEN=ваш_API_токен
get() {
  curl -fsS -H "Authorization: Bearer $TOKEN" \
    -H "X-Forwarded-Proto: https" -H "X-Forwarded-For: 127.0.0.1" "$URL$1"
}
get '/api/users?start=0&size=1000' > users.json
get /api/config-profiles > profiles.json
get /api/internal-squads > squads.json
get /api/hosts > hosts.json
get /api/nodes > nodes.json
jq -n --slurpfile u users.json --slurpfile p profiles.json \
  --slurpfile s squads.json --slurpfile h hosts.json --slurpfile n nodes.json \
  '{users: $u[0].response.users, configProfiles: $p[0].response.configProfiles,
    internalSquads: $s[0].response.internalSquads,
    hosts: $h[0].response, nodes: $n[0].response}' > remnawave-snapshot.json
```

Больше 1000 пользователей — повторите первый запрос с `start=1000`, `2000`… и
объедините массивы `users`.

## Переключение с 3x-ui

### Тот же сервер, панель целиком

Если эта панель встаёт на место старой 3x-ui на том же сервере, проще всего
перенести базу целиком: **Бэкап → Восстановить**, загрузите `x-ui.db` и **снимите**
галочку «Сохранить настройки этой машины». Переедут и пользователи, и настройки
подписок, и вход в панель. Старую 3x-ui перед этим остановите: `x-ui stop`.

### В уже настроенную панель или на ноду

Если у этой панели уже есть свои подключения и ноды, используйте окно переноса с
источником **3x-ui**: оно добавляет подключения и клиентов, ничего не стирая.

<Steps>
<Step>
### Поставьте ноду на сервер старой 3x-ui

Если старая 3x-ui работает не на сервере этой панели, добавьте на её сервер ноду
и укажите её как цель в окне переноса. Новая нода должна слушать другой порт
панели, чем старая 3x-ui.
</Step>
<Step>
### Остановите старую панель и перенесите

```bash
x-ui stop && systemctl disable x-ui
```

Загрузите `x-ui.db`, нажмите **Проверить**, затем **Перенести**. Клиенты 3x-ui
с одним `subId` под разными email объединяются в одного клиента со всеми его
подключениями, трафик суммируется.
</Step>
<Step>
### Переключите адрес подписок

Галочка «Взять пути подписок» переносит `subPath`, `subJsonPath`,
`subClashPath` и `subURI`. Остаётся, чтобы домен и порт старых ссылок вели на
сервер подписок этой панели: тот же порт (`2096` по умолчанию) и тот же
сертификат в настройках подписок, или DNS/обратный прокси.
</Step>
</Steps>
